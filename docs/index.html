Defense in Depth for LLM Agents

Compact D1–D10 controls. Prompts guide behavior; application code, permissions, schemas, filters, budgets, and approvals enforce boundaries.

Model/application boundary: the model may propose actions; deterministic code, permissions, schemas, filters, budgets, and human approval decide whether actions are allowed.

D1 · Scope + ZTA · fail closed

Deterministic: Yes

Map: Cards: ZTA, Fail Closed

Failure / control

Breaks if absent: Without it, the model can widen the task or treat all requests as authorized.

Control: Allowed task, forbidden actions, success criteria, stop conditions.

D2 · Instruction/Data Boundary · fail closed

Deterministic: Yes

Map: Cards: Trust Boundary, RAG Grounding

Failure / control

Breaks if absent: Without it, retrieved docs/web/email/tool output can become hidden instructions.

Control: Untrusted examples: webpages, emails, PDFs, logs, tool output, images, uploads.

D3 · Threat Model + STRIDE · fail closed

Deterministic: Mostly

Map: Cards: STRIDE, DREAD

Failure / control

Breaks if absent: Without it, security review becomes vibes instead of enumerated abuse paths.

Control: Spoofing, tampering, repudiation, information disclosure, denial, privilege escalation.

D4 · Capability Manifest + MCP · fail closed

Deterministic: Yes

Map: Cards: Capability Allowlist, MCP Boundary

Failure / control

Breaks if absent: Without it, tools can exceed intended paths, hosts, commands, or scopes.

Control: List tools, roots, domains, write actions, model-visible secrets, and denied capabilities.

D5 · Sandbox / Filesystem Boundary · fail closed

Deterministic: Yes

Map: Cards: Least Privilege, App-Layer Gate

Failure / control

Breaks if absent: Without it, a compromised agent can read/write outside the job boundary.

Control: Use containers, read-only mounts, allowlisted roots, and no ambient credentials.

D6 · State + ACID / Rollback · fail closed

Deterministic: Yes

Map: Cards: ACID, Rollback, RTO/RPO

Failure / control

Breaks if absent: Without it, partial writes and failed migrations corrupt state.

Control: Require backup, idempotence, rollback command, verification, and recovery target.

D7 · HITL + Separation of Duties · fail closed

Deterministic: Yes

Map: Cards: Approval Threshold, RBAC/ABAC

Failure / control

Breaks if absent: Without it, high-impact actions can happen without human judgment.

Control: Use 4-eyes approval for deletion, spending, deploy, credentials, legal/medical/financial action.

D8 · Output + Secret Egress Scanner · fail closed

Deterministic: Yes

Map: Cards: Output Filter, Secret Egress Filter

Failure / control

Breaks if absent: Without it, secrets/PII/tool traces can be returned or exfiltrated.

Control: Run deterministic filters before delivery, publishing, forwarding, or tool handoff.

D9 · Budget + Degraded Mode · fail closed

Deterministic: Mostly

Map: Cards: Backpressure, Graceful Degradation

Failure / control

Breaks if absent: Without it, retries, recursion, context growth, and cost can run away.

Control: Define max turns, queue caps, rate limits, spend caps, and safe degraded behavior.

D10 · Audit + Tamper-Evident Receipt · fail closed

Deterministic: Yes

Map: Cards: Cite or Retract, Smoke Before Claim

Failure / control

Breaks if absent: Without it, future reviewers cannot distinguish proof from claim.

Control: Record input basis, commands, diffs, hashes, tests, approvals, failures, and unverified claims.

Print-friendly defense checklist
  • Scope locked and stop conditions written.
  • Trusted instructions separated from untrusted content.
  • Tools, files, domains, commands, secrets, and write actions allowlisted.
  • Rollback/idempotence defined for state mutation.
  • HITL threshold set for high-impact actions.
  • Output scanned for secrets, PII, unsafe links, hallucinated citations.
  • Receipts kept: source basis, commands, diffs, tests, approvals, failures.

Claude + Hermes Skill Notes

Use this section to choose the right artifact surface, control skill loading, and keep skill changes evidence-based.

Skill surface decision table

SurfaceUse whenAvoid whenSource keys

General skill rules

  • Manifest fields: name, description, triggers, permissions, resources, scripts, evals, owner, version, retirement rule.
  • Progressive disclosure: trigger metadata → lean instructions → references/scripts only when needed.
  • Trigger evals: maintain should-trigger, should-not-trigger, ambiguous-trigger, and regression cases.
  • No mutation without receipt: revise a skill only from failing case → patch → eval result → changelog.
  • Coordinator verifies: delegated agents investigate or patch; coordinator checks evidence and owns final claim.

Trust + permission tiers

  • Official: vendor/platform source; still check permissions and version.
  • Repo-pinned: allowed when commit/version/hash is recorded.
  • Local-authored: acceptable with owner, test cases, and changelog.
  • Community: require source scan, permission cap, and sandbox.
  • Untrusted: read-only review only; no secrets, tools, or write actions.

Capability permission matrix

Read repo/docsAllowScope root
Write filesReviewDiff-first + rollback

Secrets/credentialsDenyServer-side only

Lifecycle + failure modes

  • Lifecycle: author → trigger eval → execute → observe → revise → release → retire.
  • Over-triggering: description too broad; add should-not-trigger cases.
  • Under-triggering: missing synonyms/acronyms; add aliases and examples.
  • Memory provenance: durable facts need source, date, scope, and correction path.
  • Skill supply chain: pin source/version/hash; scan scripts/resources before loading.
  • MCP compatibility: distinguish skill instructions/resources from external tool protocol permissions.
